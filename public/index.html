01 — About

Reliable data, built in layers.

I'm a data engineer based in Ankara, Türkiye. My work sits between messy source systems and the people who need answers from them: I ingest raw files, clean and reconcile them, and model the result into tables an analyst can query without second-guessing the numbers.

Most of what I build follows the Medallion Architecture — Bronze for data exactly as it arrived, Silver for cleaned and conformed records, Gold for business-ready star schemas and KPI tables. I've implemented that pattern end to end in Microsoft SQL Server with T-SQL stored procedures, and on Databricks with PySpark, Delta Lake and Unity Catalog — including a healthcare lakehouse covering five years of admissions and billing data. I also take data through to the decision: a Power BI analysis of a retail bank's 2025 results, ending in a memo to the CFO.

I care about the unglamorous parts: data-quality checks that run as code, scripts that can be re-run safely, and documentation the next engineer can actually use. I'm open to data engineering roles and collaborations.

04 — Approach

How I build pipelines

  1. 01

    Keep raw data raw

    Bronze stores source data exactly as it arrived. When a cleaning rule turns out to be wrong, I can fix it and replay from Bronze instead of going back to the source.

  2. 02

    Quality checks are tests

    Nulls, duplicates, business keys, domain values and financial totals are validated by scripts that live in the repo next to the pipeline — not by eyeballing a table.

  3. 03

    Re-runnable by design

    Scripts check whether objects exist before creating them, and loads are full refreshes, so running a pipeline twice gives the same result as running it once.

  4. 04

    Documented for the next person

    Each project ships with a data catalog, naming conventions and a source-to-target lineage table, so someone new can find where every column comes from.
