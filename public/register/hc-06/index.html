HC-06Checked · clean

Business keys across ten yearly files: unique

Healthcare lakehouse

What was wrong

Nothing. Splitting a table into yearly files is a common way to get duplicate IDs; these files don’t have any.

Evidence

How it was detected

Recomputed from the raw file, which is public in the project repository.

Why it matters

Unique keys are what allow billing to be joined back to admissions one-to-one.

How it was verified

A query that should return no rows after the fix.

Show the check
total_rows = billing.count()

    .distinct()
    .count()
