WH-10Resolved

Order dates stored as integers — some of them not dates

SQL Server warehouse · Databricks pipeline

What was wrong

Order, ship and due dates arrive as eight-digit integers. Nineteen order dates are 0 or have the wrong number of digits.

All 60,398 order dates are integers. 19 can’t be dates at all: 17 zeros, plus 32154 and 5489.

Evidence

How it was detected

Recomputed from the raw file, which is public in the project repository.

Why it matters

Integer dates can’t be filtered by month or compared with real dates; casting a bad one fails the whole load.

What was done

SQL Server Medallion Data Warehouse

Invalid values become NULL; the rest are cast through text to DATE.

Show the T-SQL
CASE 
    WHEN sls_order_dt = 0 OR LEN(sls_order_dt) != 8 THEN NULL
    ELSE CAST(CAST(sls_order_dt AS VARCHAR) AS DATE)
END AS sls_order_dt,

Databricks Medallion Pipeline

Same rule with an explicit yyyyMMdd pattern.

Show the PySpark
F.when(
    (col("sls_order_dt") == 0) | (length(col("sls_order_dt")) != 8),
    None
).otherwise(F.to_date(col("sls_order_dt").cast("string"), "yyyyMMdd"))

How it was verified

The same rule as a check on the raw table:

Show the check
-- Check for Invalid Dates
-- Expectation: No Invalid Dates
SELECT 
    NULLIF(sls_due_dt, 0) AS sls_due_dt 
FROM bronze.crm_sales_details
WHERE sls_due_dt <= 0 
    OR LEN(sls_due_dt) != 8 
    OR sls_due_dt > 20500101 
    OR sls_due_dt < 19000101;
